# AI usage log

I used Claude throughout (design discussion, test and code drafts, debugging). These are the specific outputs where I corrected, rejected or rewrote what the AI produced, and why.

| # | What the AI suggested or produced | What I changed | Why |
|---|---|---|---|
| 1 | An AI-generated example server split into two Maven modules (a `repository` module and a `server` module) with a root POM | Rejected it. I kept a single Spring Boot module with `domain`, `repository`, `service` and `controller` packages | A package boundary gives the same separation with far less build complexity. (The example's root POM also set `java.version` without the Spring Boot parent, so the setting would not have applied.) |
| 2 | The same example's in-memory repository assigned IDs as `clients.size() + 1` | Replaced it with an incrementing counter (`AtomicLong`), and wrote the test `idsAreNotReusedAfterADelete` first | After a delete, a size-based ID can duplicate an existing ID, and the brief requires deleting candidates |
| 3 | Injecting a `java.time.Clock` into the `Candidate` entity so timestamps could be tested | Questioned whether every candidate needs a clock, and moved time handling to the service: `Candidate.addNote(text, instant)`, with the service owning the clock | An entity should stay free of infrastructure, and it would be awkward to carry a clock once the entity is persisted with JPA. Tests stay deterministic because they use a fixed clock |
| 4 | AI review of my first notes design (one growing string, tested against `LocalDateTime.now()`) found the test could fail when the clock ticked over. It tested display formatting rather than behaviour, and made a structured notes history hard to return from an API | Rewrote notes as a `Note` record (text and timestamp) in an unmodifiable list, with tests using fixed instants | The intermittent test was untrustworthy, and the assignment wants a timestamped notes history that the page can render |
| 5 | A role filter that matched the whole role text (case-insensitive equality) | Changed it to a partial match, test-first (`listFiltersByPartOfTheRole`) | It clashed with the search box: typing part of a role showed nothing |
